# 딴짓 차단기 (Chrome Extension)

지정한 사이트의 접속을 차단하는 크롬 확장 프로그램입니다.

## 설치 방법

1. 크롬 주소창에 `chrome://extensions` 입력
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** 클릭
4. 이 `site-blocker` 폴더를 선택
5. 툴바 퍼즐 아이콘 → 딴짓 차단기를 **고정(핀)** 해두면 편합니다

## 사용법

### 차단 목록

- `naver.com` 처럼 도메인을 입력하고 **차단** → 즉시 적용됩니다
- `www.` 와 서브도메인(`m.`, `blog.` 등)은 자동으로 함께 차단됩니다
- 목록의 `✕` 로 해제, 오른쪽 위 스위치로 전체 차단 일시 중지

### 예외 목록

차단된 도메인 안에서 **이 주소만 허용**하고 싶을 때 사용합니다.

| 차단 목록 | 예외 목록 | 결과 |
|---|---|---|
| `naver.com` | `map.naver.com` | 네이버는 막히고 지도는 열림 |

- 예외는 차단보다 항상 우선합니다
- 예외도 서브도메인을 포함합니다 (`map.naver.com` 허용 시 `pcmap.map.naver.com` 도 허용, `pcmap.naver.com` 은 아님)
- 상위 차단 도메인이 없는 예외를 넣으면 "지금은 효과가 없습니다" 라고 알려줍니다

### 설정

- 차단 페이지 이모지/제목/안내 문구 변경
- 비밀번호 설정 — 걸어두면 팝업을 열 때마다 입력해야 하며, 해제 후 5분간 유지됩니다

### 진단 (문제가 생겼을 때)

팝업 맨 아래 **진단** 을 펼치면:

- **주소 테스트** — `https://map.naver.com` 을 넣고 테스트하면 통과인지 차단인지, 몇 번 규칙에 걸리는지 알려줍니다
- **규칙 다시 적용** — 크롬에 규칙을 강제로 재등록합니다
- **등록된 규칙 목록** — 크롬에 실제로 들어가 있는 규칙을 그대로 보여줍니다. 예외를 넣었는데 여기 `예외(allow)` 줄이 없다면 규칙이 적용되지 않은 것입니다
- 규칙 적용 중 오류가 나면 팝업 위쪽에 빨간 배너로 표시됩니다

> 차단 화면이 떠 있는 탭에서 **새로고침을 하면 계속 차단 화면이 나옵니다.** 그 탭의 주소는 이미 확장 프로그램 페이지로 바뀌어 있기 때문입니다. 주소창에 주소를 다시 입력해서 접속하세요.

## 동작 방식

`declarativeNetRequest` 동적 규칙으로 페이지 요청 단계에서 차단하므로 HTTPS 사이트도 로딩되기 전에 막히고, 차단 시 `blocked.html` 안내 페이지로 이동합니다.

예외는 **두 겹**으로 걸려 있습니다.

1. 차단 규칙(`redirect`, priority 1)의 조건에 `excludedRequestDomains` 로 예외 도메인을 넣어 **매칭 자체가 안 되게** 함
2. 예외 규칙(`allow`, priority 2)을 따로 추가 — 우선순위가 높아 차단을 이김

둘 중 하나만 동작해도 예외가 유지됩니다.

## 변경 이력

### 1.3.0 — 웹스토어 배포 준비 4단계
- 확장 프로그램 이름 변경: `사이트 차단기` → **`딴짓 차단기`**
- `manifest.json` 의 `description` 을 스토어 요약 문구로 교체 (57자 / 제한 132자)
- 팝업·차단 페이지의 이름 표기 일괄 변경
- 스토어 스크린샷 4종과 프로모 타일을 새 이름으로 재생성

### 1.2.1 — 웹스토어 배포 준비 2단계
- 아이콘 전면 교체 (금지 표지 디자인, 붉은 원 + 흰 가로 막대)
  - `icon128.png` 은 웹스토어 규격대로 **96×96 그림 + 사방 16px 투명 여백**
  - 툴바용 16 / 32 / 48px 추가 — 작은 크기에서도 형태가 뭉개지지 않도록 별도 조정
  - 8배 슈퍼샘플링 후 축소해 가장자리를 매끄럽게 처리

### 1.2.0 — 웹스토어 배포 준비 1단계
- **권한 구조 개편**: `declarativeNetRequest` + `host_permissions: ["<all_urls>"]` →
  `declarativeNetRequestWithHostAccess` + `optional_host_permissions: ["<all_urls>"]`.
  설치 시 "모든 웹사이트의 데이터를 읽고 변경" 경고가 사라지고, 사용자가 차단 목록에
  추가한 사이트에 대해서만 그때그때 권한을 요청한다.
  - 팝업에 권한 미허용 사이트 배너와 항목별 "권한 허용" 버튼 추가
  - 권한 요청은 클릭 핸들러에서 즉시 호출 (사용자 제스처 유지). 권한 창 때문에 팝업이
    닫혀도 백그라운드가 `permissions.onAdded` 로 규칙을 다시 적용한다
- **버그 수정**: DNR 의 `urlFilter` 는 ASCII 만 허용하는데 한글 도메인이 그대로 들어가
  규칙 등록 전체가 실패할 수 있었다. `URL` 파서로 퓨니코드(`xn--...`) 변환 후 검증하도록 수정
  - `한글.한국` → `xn--bj0bj06e.xn--3e0b707e`
  - `localhost`, IP 주소는 거부

### 1.1.1
- **버그 수정**: 서비스 워커 기동과 목록 변경이 동시에 일어나면 규칙 등록이 두 번 실행되어
  `Rule with id N does not have a unique ID` 오류로 **규칙 적용 전체가 실패**했다.
  그 결과 예외(allow) 규칙만 등록되지 않아 "차단은 되는데 예외가 안 먹는" 증상이 발생.
  - 규칙 적용을 직렬 큐로 처리해 동시 실행을 막음
  - 삭제 목록(`removeRuleIds`)에 새로 추가할 ID까지 포함시켜 ID 충돌을 원천 차단
  - 중복 호출의 원인이던 `onInstalled` / `onStartup` 리스너 제거 (서비스 워커 기동 시 한 번만 실행)
  - 실패 시 규칙을 전부 지우고 1회 자동 재시도

### 1.1.0
- 예외 목록 추가, 진단 패널 추가

## 알아둘 점

- 비밀번호는 SHA-256 해시로 저장되며 브라우저 로컬에만 보관됩니다 (초기화 시 확장 프로그램 삭제 후 재설치)
- 확장 프로그램 자체를 `chrome://extensions` 에서 끄거나 삭제하면 차단도 풀립니다. 완전히 막으려면 hosts 파일 방식이나 OS 계정 정책이 필요합니다
- 시크릿 모드에서 적용하려면 확장 프로그램 상세 화면에서 **시크릿 모드에서 허용** 을 켜야 합니다
- 예외로 연 사이트가 로그인 리디렉션(`nid.naver.com` 등)을 거치면 그 중간 주소도 예외 목록에 넣어야 정상 동작합니다

## 파일 구성

| 파일 | 역할 |
|---|---|
| `manifest.json` | 확장 프로그램 정의 (Manifest V3) |
| `background.js` | 차단/예외 목록 → 네트워크 규칙 변환 |
| `popup.html` / `popup.js` | 차단·예외 목록 관리, 설정, 비밀번호 UI |
| `blocked.html` / `blocked.js` | 차단 시 표시되는 안내 페이지 |
| `icons/` | 확장 프로그램 아이콘 |
